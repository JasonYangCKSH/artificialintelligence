## 設計說明

### A.1 Evaluation Function — Pattern 掃描邏輯

掃描方式採用「滑動視窗 + 含空格型樣」：
- 對棋盤每條線（橫、直、主斜、副斜）以長度 6 的視窗滑動
- 視窗內只有「目標色 + EMPTY」才視為有效段落，若出現對方子則截斷
- 判斷 open/closed：段落兩端是否為 EMPTY（非越界、非對方子）
- 例如 `O_OO`（跳連）在視窗中仍計為 3 子型樣，兩端開放則為 open_three

分數表（白方視角正值）：

| 型樣 | 分數 |
|------|------|
| 五連/長連 | WIN_SCORE |
| open_four | 100,000 |
| closed_four | 10,000 |
| open_three | 1,000 |
| closed_three | 100 |
| open_two | 10 |
| closed_two | 1 |

黑方分數乘以 **1.2** 懲罰係數，體現「防守優先」。

---

### A.2 Move Ordering 提升 Alpha-Beta 效率

Alpha-Beta 的剪枝效果取決於節點排序品質。排序啟發優先級：

1. **白方直接獲勝** → 最高優先（剪枝立刻發生）
2. **防守黑方五連** → 緊急防守
3. **白方形成 open_four / closed_four** → 進攻威脅
4. **防守黑方 open_four** → 阻止必勝棋型
5. **白方形成 open_three** → 佈局進攻
6. **evaluate_board 增量分** → 一般啟發排序

最佳排序下，Alpha-Beta 的搜尋複雜度從 O(b^d) 降至約 O(b^(d/2))。

---

### A.3 Transposition Table Flag 機制

每筆記錄存 `{score, depth, flag}`：

| Flag | 意義 | 使用時機 |
|------|------|----------|
| `exact` | 精確值（完整搜尋） | 可直接使用 |
| `lower` | 下界（Alpha cutoff，MAX節點） | score ≥ beta 則剪枝 |
| `upper` | 上界（Beta cutoff，MIN節點） | score ≤ alpha 則剪枝 |

查表時需確認 `stored_depth >= current_depth`，深度不足則只做 move hint 使用。

### 實作重點摘要

**`evaluate_board`**
- 分兩階段掃描：① 連續段落（精確計算 open/closed）、② 長度 6 視窗跳連偵測（分數減半，反映跳連威脅較低）
- 黑方分數 × 1.2 懲罰係數，強制 AI 優先防守

**`ordered_move`**
- 候選格限制在已有棋子周圍 `radius` 格，大幅縮小搜尋空間
- 優先級計算（`move_priority`）依序：白方直接贏 → 防守黑方五連 → 防守黑方 open_four → 白方 four → 白方 open_three → 靜態評估分

**`minimax`**
- Alpha-Beta 剪枝 + Transposition Table（`exact/lower/upper` flag 機制）
- 終局偵測依 `last_x/last_y` 判斷上一手是否已獲勝，避免多餘展開

**`choose_move`**
- 每回合開始清空 `trans_table`，防止跨回合 stale entry
- 三層快速檢查（空盤 → 白方即贏 → 防守黑方必勝）後才進入完整搜尋
- Minimax 回傳無效座標時有 fallback 保護
